# 아키텍처

> 초기 구현 기록이다. 현재 운영은 원본·WebP 썸네일을 비공개 R2에 저장하고 총 9,500,000,000바이트 예약 한도를 적용한다. Mac은 DB·인증·변환·분석과 기존 원본 복구본을 담당한다. 구체적인 전송·예약·이관·검증은 [R2 전환 계획](r2-migration-plan.md)을 따른다. 아래 초기 R2 미사용 방침과 직접 전송 제안은 이 계획으로 대체한다.

## 기준과 현재 상태

로컬 프로토타입과 mlhops 공유 사이드카가 구현되었다. `apps/web/src/server/`는 실제 인증·API 클라이언트이며, 서버는 별도 mlhops 레포의 `sidecars/phogaem/`에 있다. 기능별 프런트엔드 디렉터리 분리는 규모가 커지면 진행한다. 초기에는 작은 앱을 `App.tsx`, `domain.ts`, `storage.ts`, `styles.css`에 모아 불필요한 추상화를 줄였다.

근거 문서(개발자 로컬 체크아웃 기준):

- `../../mlhops/docs/new-app.md:31`: 브라우저 → 게이트웨이 → 코어 → 사이드카, 사용자 ID는 코어가 검증한다.
- `../../mlhops/docs/new-app.md:41`: GitHub Pages 프로젝트 경로는 기존 origin·패스키 RP를 재사용한다.
- `../../mlhops/docs/new-app.md:48`: 브라우저 저장소는 앱 경로로 이름공간을 분리한다.
- `../../mlhops/docs/new-app.md:55`: 기존 서버 클라이언트를 재사용하고 로그인은 필요할 때만 한다.
- `../../mlhops/docs/new-app.md:67`: DB 기능은 Rust 사이드카·sidecar-kit·사이드카별 스키마 패턴을 따른다.
- `../../mlhops/docs/new-app.md:134`: 게이트웨이 기본 본문 한도 20MB, IP별 요청 제한, 최대 시간 제한이 있다.

소스 참조는 이 문서 위치 기준의 로컬 경로다. 공개 레포에는 내부 원문의 내용을 복사하지 않고 통합에 필요한 계약만 기록한다.

## 역할 분리

```text
phogaem/
  apps/web/                 정적 웹앱 (React + TypeScript + Vite)
    src/features/albums/    여행 보관함·초대·멤버
    src/features/photos/    업로드 큐·필터·원본 다운로드
    src/features/viewer/    크게 보기·전체 화면·슬라이드쇼
    src/server/             기존 mlhops 인증·op 클라이언트 재사용
    src/storage/            로컬 파일·개발 데이터 접근
  tests/                    합성 파일과 사용자 시나리오
  docs/                     제품·구조·구현 계획

mlhops/                     별도 기존 레포, 사이드카 구현 완료
  sidecars/phogaem/         멤버십·메타데이터·사진 접근 권한
    migrations/             sc_phogaem 스키마
```

프런트엔드는 GitHub Pages의 `/phogaem/` 경로 배포를 목표로 한다. 지금 배포하지 않는다. 루트 package.json과 package-lock.json에서 앱·검증 의존성을 관리한다. Workers·Supabase·Firebase 등의 추가 서버를 두지 않는다.

op는 평평한 `phogaem-*` 이름과 `v1` 버전을 사용한다. 플랫폼 공통 JSON envelope는 없으므로 앱별 요청·응답 형식을 정의한다(`../../mlhops/docs/contract.md:10`).

메타데이터 요청 흐름: 브라우저 → 기존 공개 게이트웨이 → 코어 인증 → Phogaem 사이드카 → Postgres. 내부 호스트·DB 주소와 자격증명은 브라우저에 전달하지 않는다.

## 비용 없는 개발

- 기본 앱은 로컬 IndexedDB를 사용한다. 명시적으로 연결하는 공유 모드는 mlhops와 서버 로컬 파일 저장소를 사용하며 R2 코드는 없다. `.env.example`의 `PHOGAEM_STORAGE_DRIVER=local`은 향후 사이드카 설정안이며 현재 프런트엔드에서 읽는 값은 아니다.
- UI 개발은 브라우저 로컬 데이터·합성 사진으로 시작한다. IndexedDB 이름은 `phogaem:<앱 경로>`, 기기 키는 `phogaem-keys:<앱 경로>`로 분리한다.
- 서버 기능 통합은 개발용 로컬 파일 저장소와 실행마다 격리한 Postgres를 사용한다. 운영 DB·운영 사이드카에 자동 연결하지 않는다.
- R2 모드는 초기 구현에서 비활성화한다. 기본 실행·테스트·CI는 클라우드 자격증명을 요구하지 않고 R2 네트워크 요청도 만들지 않아야 한다.
- 생성된 버킷 `phogaem-photos`는 향후 연결 대상으로만 기록한다. 공개 접근과 자동 만료 규칙은 추가하지 않는다.
- 향후 R2 무료량 안에서 테스트하더라도 초과 과금 가능성이 사라지는 것은 아니다. 개발 비용 0원은 실제 R2를 사용하지 않는 방식으로 지킨다.

## 원본 전송: 후속 통합 결정

게이트웨이와 코어는 업로드 본문을 메모리에 모으므로 큰 원본을 그대로 보내는 데 제한이 있다(`../../mlhops/crates/gateway/src/lib.rs:307`, `../../mlhops/crates/core/src/api.rs:163`). JSON/base64로 감싸면 크기도 늘어난다. 응답은 공통 프록시에서 스트리밍하지만 업로드는 별도 검토가 필요하다(`../../mlhops/crates/common/src/proxy.rs:101`). 우선 로컬에서 원본 전송을 검증한다.

현재 공유 모드는 raw 원본을 기존 게이트웨이에 전달하며 파일당 16MiB로 제한한다. 실제 코어·게이트웨이·사이드카 경로의 바이트 보존을 검증했다.

향후 R2 연결 제안은 사이드카가 멤버십·파일 크기·허용 작업을 확인하고, 비공개 R2의 특정 객체에만 유효한 짧은 만료시간의 서명 URL을 발급하는 것이다. 브라우저는 파일 본문만 R2로 직접 전송한다. 자격증명은 서버에만 둔다.

이는 기존 ‘브라우저는 게이트웨이 주소 하나만 안다’ 원칙에 **파일 데이터 전송에 한정한 예외**를 도입하는 제안이다. 아직 확정·구현되지 않았다. R2 단계 진입 전에 예외 수용 여부, CORS, 서명 조건, 업로드 완료 검증을 확정한다. 예외 없이 원본을 프록시하려면 기존 바이너리 응답·크기·타임아웃 동작을 먼저 검증해야 한다. 공유받은 S3 엔드포인트는 공개 사진 URL이 아니다.

## 데이터와 권한

- `albums`: 여행 공유보관함, 생성자, 제목.
- `album_members`: `(album_id, user_id)`와 역할. 타인의 업로드도 같은 보관함 멤버라면 조회·다운로드할 수 있다.
- `album_invites`: 추측하기 어려운 토큰의 해시·만료·사용 제한. 초대 수락 후 멤버십 생성. 초대 링크 자체를 원본 공개 주소로 쓰지 않는다.
- `photos`: 보관함, 파일 해시, 원본 크기·형식, 내부 저장 키, 촬영시각(없으면 업로드 시각), 업로드 상태.
- `photo_contributions`: 사진과 업로더 관계. 같은 원본을 여러 명이 올려도 각자의 업로드 기록을 보존한다.
- `download_events`: 사용자와 사진별 다운로드 요청·사용자 확인 기록. 실제 기기 파일 존재를 보장하지 않는다.

모든 사진·초대·다운로드 op는 코어가 전달한 사용자 ID와 앨범 멤버십을 함께 검사한다. `uploaded_by = 현재 사용자`만 적용하면 친구 사진이 보이지 않으므로 공유 권한을 멤버십으로 표현한다. 인증은 기존 기기 키·패스키 흐름을 재사용하고 토큰은 메모리에만 둔다.

## 사진 동작

- 원본 보존. 초기 중복은 같은 앨범 내 SHA-256과 크기가 같은 파일이다. 파일명이나 비슷한 장면만으로 합치지 않는다.
- 업로드 전 중복 안내, 서버 측 원본 검증, 동시 업로드에 대한 유일성 제약을 모두 둔다. 브라우저가 보낸 해시만 믿고 다른 멤버의 사진으로 연결하지 않는다.
- 초기 필터는 내 업로드 포함/제외, 다른 사람 사진, 중복 업로드 기록, 다운로드 기록 없음. 조합 규칙을 단위 테스트한다.
- 다운로드는 원본 개별 저장부터 구현한다. ‘다운로드 요청됨’과 ‘받았음 확인’을 구분하고 필터 기준을 화면에 밝힌다. 취소·실패를 완료로 기록하지 않고 기록을 되돌릴 수 있게 한다.
- 선택 일괄 다운로드는 취소·재시도·브라우저 다중 다운로드 제한을 검증한 뒤 추가한다. 큰 원본 전체를 한 번에 메모리 ZIP으로 만들지 않는다.
- 큰 화면은 반응형 뷰어, 키보드 좌우·Escape, 전체 화면, 슬라이드쇼가 1차 범위다. TV 시청은 우선 PC 연결·화면 미러링을 전제로 하며 TV 전용 앱·직접 캐스팅은 후속 범위다.
- JPEG·PNG·WebP 미리보기부터 검증한다. HEIC 등 브라우저가 표시하지 못하는 형식은 원본 다운로드와 안내를 제공한다. 자동 변환·Live Photos·영상은 후속 결정이다.

## 수명과 후속 범위

삭제 UI와 자동 만료는 현재 구현하지 않는다. 보관 기한도 임의로 정하지 않는다. 초기 화면에는 영구 보관을 약속하지 않고 원본 별도 보관을 안내한다. 향후 삭제 시 DB·원본·썸네일·실패한 업로드를 함께 정리할 수 있도록 저장 키와 상태를 분리한다.

현재 공유 모드의 설정·제한·검증 방법은 [integration.md](integration.md)를 따른다. R2 전송 예외는 여전히 후속 결정이다.
