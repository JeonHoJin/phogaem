# 보관함 사진 알림

알림은 보관함과 기기별 선택 기능이다. 승인된 보관함 멤버가 종 아이콘을 누른 경우에만 시스템 권한을 요청하고 해당 기기를 등록한다. 한 보관함의 알림을 꺼도 다른 보관함의 구독은 유지한다. iPhone/iPad는 iOS/iPadOS 16.4 이상의 홈 화면 웹앱에서 사용한다.

## 발송 범위

새 원본 업로드가 성공한 트랜잭션에서만 발송 대기를 저장한다. 동일 파일 재업로드와 실패한 업로드는 제외한다. 업로드가 30초간 잠잠해지면 묶어서 보내며, 계속되는 업로드는 최대 5분 단위로 나눈다. 대기를 저장할 때만 멤버를 고정하지 않고, 발송할 때 현재 멤버·해당 보관함의 기기별 알림 설정을 다시 조회한다. 업로더의 모든 기기와 다른 보관함의 멤버는 제외한다.

푸시 서비스로 보내는 내용은 불투명한 알림·보관함·수신자 ID와 개인정보 없는 `포갬 / 새 사진` 기본 표시뿐이다. 사진, 보관함 이름, 닉네임, 사진 수는 포함하지 않는다. 서비스 워커가 기존 기기 키로 새로 인증해 승인·수신자·현재 멤버십·구독을 확인한 뒤에만 상세 내용을 표시한다. 알림에서 보관함을 열 때도 기존 접근 권한 검사를 따른다.

Safari의 일반 Web Push는 모든 수신 이벤트에 화면 알림을 요구한다. 따라서 네트워크 오류, 계정 전환, 권한 변경, 중복 수신에서도 기본 알림은 표시한다. 확인에 성공하면 같은 태그의 알림을 보관함 이름·사진 수로 갱신한다. 이미 OS 푸시 서비스에 전달한 기본 알림은 뒤늦은 구독 해제나 멤버 삭제로 회수할 수 없다. [WebKit의 표시 및 선언형 푸시 설명](https://webkit.org/blog/16535/meet-declarative-web-push/)

## 운영

서버는 기존 Web Push 전송 구현을 공용 라이브러리로 재사용한다. 추가 외부 패키지나 Cloudflare 제품은 필요하지 않다. 포갬은 다른 앱과 별개의 `~/.config/mlhops/phogaem-vapid.key`를 사용한다. 키와 활성화 파일은 소유자 전용 0600 일반 파일이며 저장소에 넣지 않는다.

`~/.config/mlhops/phogaem-push.json`:

```json
{"enabled": true}
```

명시적 `PHOGAEM_PUSH_ENABLED=true/false` 환경변수가 파일보다 우선한다. 없거나 잘못된 설정은 알림만 비활성화한다. 프런트 공개 Actions 변수 `PHOGAEM_PUSH_ENABLED=true`가 종 아이콘을 켠다. 백엔드를 먼저 적용하고 프런트를 배포한다. 개발 통합 스택은 알림을 명시적으로 끄며 실제 푸시 서비스나 운영 키를 사용하지 않는다.

알림 작업은 DB에 저장되고, 제한된 재시도·임대와 동일 태그로 중복을 억제한다. HTTP 발송과 서비스 워커 작업에는 시간 제한이 있다. 서비스 종료 신호로 작업을 취소하고 기다리며 별도 OS 프로세스를 생성하지 않는다. 오래된 알림 데이터는 48시간 후 정리한다. DB 마이그레이션 후 기능을 되돌릴 때는 새 바이너리를 유지하고 활성화 파일을 false로 바꾼다.

## 검증

- 백엔드 합성 DB/HTTP 테스트: 다른 보관함·업로더 제외, 탈퇴·알림 해제·만료 구독, 재시도·재시작, 중복·실패 업로드, 임의 엔드포인트 차단.
- 단위 테스트: 사용자 권한 요청 시점, 계정 전환, 기존 키 없는 백그라운드 실행, 시간 제한과 안전한 보관함 주소.
- `npm run test:push`: 별도 `.local/push-dist`에서 실제 서비스 워커와 Chrome의 합성 푸시 이벤트를 검증한다. 운영용 `dist`를 덮어쓰지 않는다. 실제 공급자나 사용자에게 알림을 보내지 않는다.

설치형 iPhone의 잠금 화면 수신은 실제 기기의 권한 허용 후 별도로 확인해야 한다.
