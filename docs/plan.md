# 초기 구현 계획

> 아래는 초기 구현의 이력이다. 최신 UI/UX 목표는 [DESIGN.md](../DESIGN.md), 사용자 흐름과 다음 화면 변경 순서는 [사용자 흐름](user-flow.md)을 따른다. 2026-11-05부터 모든 일반·예외 화면에 안내 문구를 표시하지 않는 것이 설계 조건이다. 현재 배포 화면의 전환은 후속 구현 대상이다.

## 요구사항

4명 정도의 여행 멤버가 사진을 함께 올리고, 중복·내 사진·받은 사진을 걸러 필요한 원본을 선택해 내려받는다. 휴대폰 업로드와 큰 화면 감상을 지원한다. 개발 중 Cloudflare 비용은 0원으로 유지하며 실제 R2를 사용하지 않는다. 삭제·공개 출시·자동 만료는 후속 범위다.

구조의 근거와 설계 결정은 [architecture.md](architecture.md)에 기록했다. 현재 1·2단계의 로컬 프로토타입이 구현되었고 단위 테스트 9개와 브라우저 시나리오 11개, 타입 검사·린트·빌드가 통과했다. 3단계 mlhops 서버 통합도 구현·검증되었다. 운영 설치·공개 배포와 4단계 R2 연결은 아직 진행하지 않았다. 일괄 ZIP 다운로드는 후속 검증 대상으로 남긴다.

## 1. 로컬에서 작동하는 공유보관함 화면

예정 경로: `apps/web/`, `tests/`.

- 정적 React·TypeScript·Vite 웹앱 뼈대, `/phogaem/` 배포 경로, 앱별 브라우저 저장소 이름을 설정한다.
- 합성 사용자 4명과 합성 사진으로 보관함·사진 격자·필터·선택 UI를 구현한다.
- 파일 업로드·SHA-256 완전 중복 판정·로컬 원본 보관을 연결한다. 파일 크기 제한·브라우저 저장소 용량 초과를 표시한다.
- 크게 보기, 키보드 이동, 전체 화면, 슬라이드쇼를 구현한다.

완료 기준: 네트워크를 차단해도 합성 보관함을 열 수 있다. 동일 바이트·다른 파일명은 중복이고, 같은 이름·다른 바이트는 별개다. 새로고침 후 로컬 사진·필터 상태를 복원한다. 390px와 1920px 화면에서 선택·뷰어가 동작하고 Escape로 닫힌다. HEIC 미리보기 실패가 전체 화면을 깨뜨리지 않는다.

## 2. 다운로드 상태와 선택 다운로드

예정 경로: `apps/web/src/features/photos/`, `tests/`.

- 필터 조합과 선택한 원본의 개별 다운로드를 구현한다.
- 다운로드 요청·사용자 수령 확인·취소·실패·재시도를 구분한다.
- 일괄 다운로드는 브라우저 제한과 메모리 사용을 검증한 뒤 연결한다.

완료 기준: 내 업로드·중복·받았음 필터를 조합해 기대한 파일만 선택한다. 실패·취소는 수령 확인으로 기록되지 않는다. 받은 기록을 되돌릴 수 있다. 내려받은 합성 파일의 바이트 해시가 업로드 원본과 같다.

## 3. mlhops 인증·공유 메타데이터·로컬 파일 통합

예정 경로: `apps/web/src/server/`; 별도 mlhops 레포의 `sidecars/phogaem/`, 마이그레이션, 등록 설정.

- `../../schedule-parser/apps/mobile/src/server/{client,index,passkey}.ts`를 기준으로 인증 클라이언트를 재사용한다. 앱 이름공간만 조정하고 기존 동작을 유지한다.
- Rust·sidecar-kit 패턴으로 멤버십·초대·사진·다운로드 기록 op를 구현한다. 이름은 평평한 `phogaem-*`, 버전은 `v1`로 통일한다.
- 테스트 DB와 로컬 파일 저장소로 4개 독립 사용자·2개 보관함의 공유를 검증한다. 파일 전송 방식은 게이트웨이 계약을 먼저 확인한다.
- 운영 설치·배포는 개발 통합과 분리한다. 포트·DB 스키마·매니페스트는 구현 당시 충돌 여부를 재확인한다.

완료 기준: 첫 화면에서는 로그인 요청이 없다. 멤버는 다른 멤버의 사진을 받고, 비멤버는 사진 ID·앨범 ID를 알아도 목록·원본·다운로드 기록을 읽거나 수정하지 못한다. 만료된 초대는 거절된다. 동시 동일 파일 업로드가 중복 원본을 만들지 않으며 업로더 기록은 남는다. 기본 통합 테스트는 R2에 요청하지 않는다.

## 4. 후속 R2 연결 (현재 실행하지 않음)

사용자가 실제 연결을 지시한 이후 진행한다. 대상은 기존 비공개 Standard 버킷 `phogaem-photos`다.

- [아키텍처](architecture.md)의 데이터 전송 예외와 큰 파일 처리 방식을 확정한다.
- 서버 전용 최소 권한 자격증명, 짧은 만료의 객체별 서명 URL, 제한적인 CORS, 원본 검증을 연결한다.
- 무료량과 별도로 업로드 용량·파일 수·동시성·요청 수 제한을 구현한다. 앱 제한만으로 계정 전체 과금을 완전히 차단할 수 있다고 주장하지 않는다.
- 실제 연결 전까지 자동 테스트에는 로컬 저장소만 사용한다.

완료 기준: 기본 실행은 여전히 로컬이다. 프런트엔드 빌드에 자격증명이 없다. 만료된 URL과 범위를 벗어난 객체 접근이 실패한다. 공개 버킷 전환 없이 멤버만 원본을 조회한다. 실제 전송 검증은 개발 비용 정책을 재확인한 뒤 별도 실시한다.

## 검증과 위험

- 문서 단계: 상대 링크, 참조 원문, Git diff, 공개 파일의 비밀값·계정별 주소 포함 여부를 검사한다. 실행 코드가 없으므로 앱 테스트·타입 검사·빌드는 아직 대상이 아니다.
- 구현 단계: 필터·해시·다운로드 상태 단위 테스트 → 로컬 통합 테스트 → 타입 검사·린트·정적 빌드 → 휴대폰·데스크톱 브라우저 시나리오 순으로 검증한다.
- 로컬 브라우저 저장소는 기기 간 공유가 아니다. 실제 4명 공유는 3단계 이후 가능하다.
- 브라우저는 파일 저장 완료를 확실하게 알려주지 않을 수 있다. 제품 문구와 필터는 기록 종류를 명시한다.
- 비슷한 사진과 완전 동일 파일은 별개다. 장면 유사도·화질 비교는 초기 중복 제거에 포함하지 않는다.
- 모바일 저장소 부족·HEIC 미리보기·대량 다운로드는 실패 경로를 먼저 만들고 원본을 보존한다.
- R2 무료량은 비용 상한이 아니다. 실제 클라우드 사용을 차단하는 로컬 기본값으로 현재 비용 정책을 충족한다.

## 현재 작업의 종료 조건

로컬 업로드·중복·필터·원본 다운로드·기록·뷰어가 동작하고 단위 테스트, 타입 검사, 린트, 정적 빌드, 브라우저 시나리오가 통과하면 로컬 프로토타입 단계를 마친다. 실제 기기 간 공유·R2 연결·배포는 후속 단계로 명시한다. 실제 R2 호출과 운영 인프라 변경은 하지 않는다.

## 검증 기록 (2026-11-04)

- `npm test`: 9개 통과. 해시·필터 AND·사용자별 수령 구분·잘못된 파일 검증.
- `npm run test:e2e`: Chrome에서 11개 통과. 원본 다운로드 SHA-256 일치, 동시 업로드 중복 통합, 잘못된 배치의 원자적 거절, 필터와 사용자 설정 복원, HEIC 대체 표시, 뷰어 키보드·포커스·전체 화면 진입과 종료, 열린 앱의 오프라인 사용, 390px/1920px 레이아웃.
- `npm run build`, `npm run lint`, `npm audit`: 통과, 알려진 의존성 취약점 0개.
- 로컬 스크린샷: `test-results/phogaem-desktop.png`, `test-results/phogaem-mobile.png`. 실제 화면 검토 완료.
- 읽기 전용 독립 코드 검토에서 수정 필수 결함은 발견되지 않았다.
- 운영 mlhops 변경·실제 R2 호출·배포 없음.

## mlhops 통합 검증 기록

- 프런트엔드 `npm test`: 21개 통과. 실제 서명 계약, 로그인 지연, 토큰 보관, 401 재인증, raw 업로드와 원본 요청 큐 포함.
- 기본 로컬 브라우저 시나리오 11개 통과. 공유 브라우저 시나리오 4개 통과.
- 공유 테스트는 실제 코어·게이트웨이·사이드카·격리 PostgreSQL을 사용했다. 4개 계정·2개 보관함, 위조 ID 차단, 원본 보존, UI 초대와 수령, 패스키 기기 연결, 전환 실패 후 복구를 확인했다.
- mlhops `cargo test --workspace --locked` 전체 통과. 기존 외부 실제 푸시 서비스 테스트 1개는 의도적으로 ignored 상태다. Phogaem 단위 2개·실제 DB HTTP 4개가 포함된다.
- Phogaem 사이드카 Clippy `-D warnings`·fmt 검사, 프런트엔드 타입 검사·린트·빌드 통과.
- 기존 schedule-parser에서 복사한 기기 연결 서명 문구를 현재 코어의 `mlhops-link-v1` 계약으로 수정했다. schedule-parser 원본은 이번 작업에서 수정하지 않았다.
- 운영 DB·코어·게이트웨이 코드·배포 설정·Cloudflare는 변경하지 않았다. 서버 미리보기는 별도 격리 개발 스택이다.
