# R2 전환 계획

2026-11-05. 전환 구현·검증 후 운영 R2 연결을 활성화했다. 기존 원본 8개는 재다운로드 해시 검증을 거쳐 이관했고 Mac 복구본은 유지했다. 아래는 구현과 검증의 기준 계획이다. 기존 '실제 R2 사용 금지' 개발 방침은 사용자의 최신 지시로 운영 R2 사용과 총 9.5GB 제한으로 변경한다. 기본 자동 테스트는 계속 로컬 합성 데이터만 사용한다.

## 요구사항과 목표 구조

- 기존 비공개 Standard 버킷 `phogaem-photos`에 원본과 WebP 썸네일을 저장한다. Mac은 인증·메타데이터·변환 작업을 담당하며 원본의 영구 저장소 역할을 R2로 옮긴다.
- 원본+썸네일+진행 중 쓰기의 합계가 **9,500,000,000바이트**를 넘는 업로드는 시작하지 않는다. 다른 버킷은 없다는 사용자 확인을 전제로 한다. GiB로 계산하지 않는다.
- 계정 승인·보관함 멤버십·중복 원본 통합·수령 상태·문구 없는 UI를 유지한다.
- 1차 전환의 파일 경로는 브라우저 → 기존 gateway/core → Phogaem → R2다. 서버가 실제 바이트 수와 SHA-256/형식을 검증한 뒤 쓰므로 엄격한 예약 한도를 적용하기 쉽다. 기존 파일당 16MiB 제한과 최대 2개 업로드를 유지한다.
- 썸네일과 원본 조회도 기존 승인 경로를 통해 전달한다. 버킷 공개·Workers·Cloudflare Images는 사용하지 않는다. 직접 업로드/서명 URL은 이번 전환 범위에서 제외하고, 이후 큰 파일 지원과 필요성을 별도로 검토한다.

현재 서버 원본 쓰기와 읽기는 `../mlhops/sidecars/phogaem/src/lib.rs:520`, `:543`, `:628`, DB 초기화는 `src/store.rs:7`에 있다. 프런트 원본 조회/미리보기는 `apps/web/src/App.tsx:49`, `:61`, 전송 클라이언트는 `apps/web/src/server/api.ts:137`, `:214`다. 아래 단계는 이 지점의 교체·확장을 기준으로 한다.

## 1. 저장소 어댑터와 안전한 연결

`../mlhops/sidecars/phogaem/`에 local/R2 저장소 어댑터를 둔다. 기존 원본 검증 코드는 유지하고 저장·조회·삭제/확인 동작만 교체한다. S3 호환 Rust 클라이언트는 공식 R2 호환성과 SDK 동작을 비교한 뒤 최소 의존성으로 선택한다.

R2 전용 자격증명은 해당 버킷의 객체 읽기/쓰기로 제한하고 Mac의 사용자 소유 0600 비밀 파일로 읽는다. 프런트 환경변수·로그·공개 레포에 넣지 않는다. 기존 launchd 정의를 가능한 한 유지하도록 기본 비밀 파일 경로/설정을 지원한다. 필요한 정의 변경 여부는 배포 전에 확인한다.

검증: 로컬 어댑터로 기존 원본 해시·승인·IDOR 테스트를 유지한다. R2 테스트 더블에서 PUT/GET 실패·타임아웃과 자격증명 누락 시 fail-closed를 확인한다. 실제 버킷 smoke는 합성 파일 1개 수준으로 별도 수행하고 확인된 테스트 객체만 삭제한다.

## 2. 전역 9.5GB 한도

새 DB 마이그레이션에서 객체 키·종류·변환 버전·저장 위치·실제 크기·작업 상태와 전역 저장 예산/예약을 기록한다. 대상은 모든 보관함의 원본과 썸네일이며 현재 보관함당 2GiB·2,000장 제한도 유지한다(`src/lib.rs:25` 주변 및 `:584`).

예약은 DB 잠금/원자 갱신으로 수행하고 네트워크 PUT 동안 DB 트랜잭션 잠금을 계속 잡지 않는다. 동일 키의 중복 업로드·썸네일 작업은 중복 예약하지 않는다. 원본은 서버가 확인한 실제 바이트 수, 썸네일은 정한 출력 상한(초기 후보 128KiB)을 미리 예약한다. 출력이 상한을 넘으면 낮은 품질/크기로 재생성하거나 생성 실패로 처리하고 상한 밖으로 쓰지 않는다.

PUT 전에 예약 → PUT 성공/객체 확인 → 확정 사용량 전환 순서다. 실패가 확실하고 객체가 없음을 확인한 예약만 해제한다. 타임아웃·프로세스 종료처럼 객체가 생겼는지 불분명하면 예약을 유지하고 확인 작업으로 복구한다. 만료 시간만 보고 예약을 해제하면 안 된다. 삭제는 R2 삭제가 확인된 뒤 차감한다. DB와 R2의 불일치/고아 객체가 발견되면 새 쓰기를 막고 재집계한다.

원본 검증 완료 이전 데이터와 변환 중 파일은 Mac 임시 공간에만 두며 작업 종료/중단 시 정리한다. R2에는 정해진 객체 키에 한 번의 PUT을 우선 사용해 multipart 미완료분을 만들지 않는다. 임의 덮어쓰기·캐시 버전 교체도 일시적으로 두 객체가 존재하는 만큼 예약한다.

검증: 합계가 한도와 정확히 같은 쓰기는 허용, 1바이트 초과는 차단한다. 동시 사용자·동일 해시·다른 보관함·썸네일 동시 생성·PUT 성공 뒤 DB 확정 실패·중단 후 재시작·삭제 실패에서도 사용량을 과소 계산하지 않아야 한다. 관리 경로에서 버킷 실측과 DB를 대조하되 매 사진 조회마다 LIST를 하지 않는다. 이 장치는 앱의 저장 용량 제한이며 과거 사용량의 청구나 요청량 청구를 취소하지 않는다.

## 3. WebP 썸네일 생성과 재사용

원본 해시당 한 번, 앨범 범위와 변환 버전을 포함한 키에 저장한다. 후보는 긴 변 최대 640px·WebP 손실 압축 품질 65~75다. 작은 원본은 확대하지 않는다. 원본은 변환/덮어쓰지 않는다. 결과 크기·미리보기 품질로 설정을 확정한다.

현재 Mac의 `sips --formats`에는 WebP가 읽기 형식으로만 표시되고 Writable이 없다. JPEG 합성 실험 성공을 WebP 인코딩 지원으로 간주하면 안 된다. 따라서 WebP 손실 인코더와 HEIC 입력 경로를 별도 선정·검증한다. 확인한 [image WebPEncoder 0.25.10](https://docs.rs/image/0.25.10/image/codecs/webp/struct.WebPEncoder.html)는 무손실만 지원한다. 손실 압축 후보인 [webp Encoder 0.3.1](https://docs.rs/webp/0.3.1/webp/struct.Encoder.html)는 libwebp 네이티브 의존성과 Mac 빌드 검증이 필요하며 HEIC 디코딩 지원은 별도다. 필요한 새 의존성과 설치 단계는 구현 전에 명시한다. 검토 근거와 생성·권한·캐시 분리는 [thumbnail-cache.md](thumbnail-cache.md)를 따른다.

작업 큐 동시성은 1부터 시작하고 픽셀·프레임·시간·메모리·출력 크기를 제한한다. 별도 변환 프로세스로 처리하며 EXIF 방향·투명도·색상/HDR·HEIC·손상 파일을 합성 데이터로 검증한다. GPS 등 원본 메타데이터를 썸네일에 그대로 복사하지 않는다. 실패 시 원본은 사용할 수 있고 썸네일만 실패 상태로 남긴다. 재시작 시 미완료 작업을 안전하게 재개한다.

검증: 동일 원본의 중복 업로드로 두 번째 변환/객체가 생기지 않음, 출력이 실제 WebP임, 크기/방향/상한 준수, 128KiB 예약 내 저장, 손상/거대 이미지의 제한 시간 내 실패.

## 4. 목록은 썸네일, 감상·다운로드는 원본

썸네일 준비 상태와 보호된 조회 op를 추가한다. `App.tsx`의 Preview가 격자에서 썸네일을 사용하고 큰 뷰어/개별 다운로드/ZIP은 기존 원본 경로를 사용하도록 분리한다. 업로드마다 사진 목록 즉시 갱신은 유지한다. 준비 중인 썸네일은 placeholder로 두고 자동으로 원본을 대신 내려받지 않는다.

서버 R2 객체가 생성 캐시이며 우선 브라우저 영구 캐시는 추가하지 않는다. 썸네일 응답도 승인·멤버십을 검사하고 `private, no-store`를 유지한다. 같은 사진을 미리보기/선택했다고 수령 확인으로 기록하지 않는다. 용량 부족은 기존 무문구 UI의 수치·파일 상태·선택 해제/재선택으로 처리하고 같은 요청의 무의미한 반복을 막는다.

검증: 격자 네트워크에 원본 GET이 없음, 뷰어/다운로드는 원본 바이트 동일, 재조회 시 썸네일 재생성 없음, 미승인/비멤버/승인 취소 차단, 썸네일 생성 실패에도 원본 다운로드 가능.

## 5. 기존 Mac 원본 이관

우선 메타데이터/원본의 개수·합계·유실/변조 여부를 읽기 전용으로 점검하고 DB와 현재 바이너리를 백업한다. 이관 명령은 dry-run, 재개, 대상별 성공 기록을 지원한다. 초기 이관 동안 새 업로드만 잠깐 중지하고 기존 조회는 유지한다.

각 원본에 대해 같은 9.5GB 예약 절차 → R2 복사 → R2에서 읽은 바이트의 SHA-256/크기를 원본과 비교 → 객체별 저장 위치를 R2로 확정한다. ETag를 SHA-256이라고 간주하지 않는다. 썸네일은 별도 예약/작업으로 생성한다. 실패 객체는 로컬 위치를 유지하고 재개 시 성공 객체를 중복 업로드하지 않는다.

전환 검증이 끝나도 Mac 원본을 바로 삭제하지 않는다. 임시 복구본으로 보존하고 정리는 별도 단계로 둔다. R2로 새로 들어온 파일은 로컬 복구본이 없으므로 전환 뒤 단순히 전체 driver를 local로 바꾸면 안 된다. 롤백은 새 쓰기를 중지하고 객체별 위치를 읽는 호환 버전으로 수행하거나 신규 R2 원본을 먼저 역복사해야 한다.

검증: 모든 기존 사진의 개수·해시·참여자·받은 기록 일치, 이관 중단/재개 시 중복 차감·누락 없음, 이관 실패 사진도 기존 경로로 조회 가능, 한도 부족이면 다음 복사 전에 중지.

## 6. 배포와 종료 기준

격리 로컬 DB+저장소 더블 검증 → 제한된 실제 R2 합성 smoke → 업로드 일시 중지/백업/이관 → Phogaem 백엔드만 갱신 → 프런트 배포 → 기존 승인 계정으로 원본/썸네일 경로 확인 → 업로드 재개 순서다. 테스트를 위해 운영 계정을 새로 승인하지 않는다. 관리자 인증이 필요한 launchd 변경은 최종 설정 비교로 판단한다. 기존 Phogaem 업데이트 경로는 `../mlhops/deploy/mac/install-phogaem.sh:21`부터다.

완료 조건: 운영 원본·썸네일 저장 위치가 R2이고, 매 업로드 완료 시 사진이 보이며, 9.5GB 경계/동시성/중단 복구가 검증되고, 권한·원본 보존·무문구 UI 테스트가 통과해야 한다. Mac 원본 복구본의 삭제는 종료 조건에 포함하지 않는다. 코어·Postgres·다른 앱 재시작과 Cloudflare 유료 이미지 서비스 추가는 필요하지 않다.

## 준비물

버킷 전용 R2 자격증명의 안전한 서버 설정과 WebP 인코더 선택이 필요하다. 비밀값을 채팅에 보내거나 프런트에 넣지 않는다. 현재 계획 작성에서는 비밀값 조회·서비스 설정 변경·R2 네트워크 요청을 수행하지 않았다.
