# 계정 승인과 패스키

Phogaem 공유 API 13개는 모두 `auth: approved`다. 코어가 관리자 승인을 매 요청 검사한 뒤 사용자 ID를 전달하고, 사이드카는 보관함 멤버십을 추가 검사한다. 초대 링크는 계정 승인을 대신하지 않는다. 브라우저 전용 기기 보관함은 서버 자원을 사용하지 않는다.

승인 대상은 개별 패스키가 아니라 mlhops 계정이다. 승인 여부는 같은 코어의 모든 `approved` op에서 공유된다. 로그인은 기기 키 또는 패스키로 하며 매 요청마다 패스키 확인창을 띄우지 않는다. 승인 취소는 토큰 만료를 기다리지 않고 다음 요청부터 403으로 반영된다.

## 다른 웹앱의 기존 패스키

`jeonhojin.github.io` 아래 다른 웹앱이 같은 mlhops 코어·RP·허용 origin을 사용하면 기존 패스키로 같은 계정에 로그인할 수 있다. 기기 키와 토큰은 앱별로 분리하므로 새 앱의 ‘이 기기로 연결’은 별도 미승인 계정을 만들 수 있다. 기존 승인 계정은 ‘패스키로 기존 계정 연결’을 사용한다.

현재 `localhost` 개발 스택은 운영 서버와 DB·RP가 달라 운영 패스키나 승인을 재사용하지 않는다.

## 승인 대기 화면

미승인 계정에는 계정 코드, 승인 재확인, 기존 패스키 로그인, 첫 패스키 등록을 제공한다. 첫 패스키를 등록해도 사진 접근 권한은 생기지 않는다. 승인 후에는 다시 확인을 누르면 된다. 초대 링크로 들어왔다면 승인 확인 또는 로그인 성공 뒤 별도 참여 버튼 없이 해당 보관함으로 이어진다. 승인이 취소되어 다음 요청이 거절되면 공유 사진·선택·뷰어를 비우고 대기 화면으로 돌아간다.

실제 운영 승인은 기존 mlhops 관리 화면에서 한다. 로컬 개발 스택은 시작할 때 **Local approval admin** 주소를 출력한다. 이 관리 화면은 loopback에만 열며 정상 개발 실행에서는 자동 승인하지 않는다. 통합 테스트만 격리된 합성 계정에 실제 관리 API로 승인·취소를 수행한다.

## 개발 서버 데이터 보존

기존 개발 데이터를 보존해 다시 띄울 때는 해당 스택의 소유 프로세스를 정상 종료한 뒤 다음 명령을 사용한다. 실행 중인 클러스터·외부 경로는 거절한다.

```sh
python3 scripts/dev-mlhops.py --reuse-run .local/dev-mlhops/run-<existing-id>
```

계정·원본·스키마·JWT 키·등록 토큰은 보존하고 로컬 포트만 새로 선택한다. 프런트엔드는 새로 출력된 `VITE_MLHOPS_API_BASE`로 다시 실행한다.

## 검증

실제 코어·게이트웨이를 통해 8개 op의 미승인 403/미인증 401, 초대 우회 차단, 승인 후 같은 토큰 허용, 취소 후 즉시 차단, 대기 중 첫 패스키 등록, 화면의 대기·복구를 확인했다. 공유 브라우저 시나리오 5개와 기본 로컬 브라우저 11개, 프런트엔드 단위 22개가 통과했다. 사이드카 단위 3개·Clippy·fmt, 프런트엔드 타입 검사·린트·빌드도 통과했다.

운영 계정 승인·운영 DB·운영 서비스는 이번 작업에서 변경하지 않았다.

## 초대 링크 진입

기존 승인 계정은 저장된 로그인 재개 또는 열린 앱의 hash 변경으로 초대를 받으면 자동 참여 후 해당 보관함을 연다. 로그인되지 않은 새 브라우저는 명시적 로그인/시작을 먼저 하며, 링크만으로 계정 생성이나 승인 우회를 하지 않는다. 초대 진입에는 생성 폼이 없고, 만료·재발급으로 무효가 된 링크는 사용할 수 없는 초대 아이콘과 대체 링크 입력, 네트워크 실패는 재시도를 제공한다. 초대 화면을 닫으면 자동 참여를 취소하고 URL의 토큰을 지운다. 성공 시 이전 보관함의 사진 필터를 초기화한다.

## 보관함 닉네임

보관함 멤버의 닉네임은 계정 승인과 별개이며 보관함마다 저장한다. 첫 입장 시 본인 닉네임을 입력하고, 기존 닉네임 없는 멤버도 다음 입장에 설정한다. 주인도 본인 이름을 설정한다. `POST phogaem-member-name-set/v1 {albumId,nickname,userId?}`는 본인 이름만 바꿀 수 있으며 다른 사람의 이름을 변경하지 못한다. 빈 이름·제어문자·24자 초과를 거절하고 UI는 문자열을 텍스트로 렌더링한다. 초대 및 생성 API의 nickname은 이전 클라이언트를 위해 선택 필드다.
