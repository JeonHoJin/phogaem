# 분석 기반 비교 후보

업로드 후 저장한 Gemma 분석 결과를 읽어 같은 공유보관함 안의 비교 후보를 만든다. 공유보관함을 열 때 조회하며, 후보 조회 자체가 추론·이미지 변환·R2 쓰기를 실행하지 않는다.

## 후보 기준과 한계

현재 버전의 분석이 성공했고 스키마가 유효한 사진만 사용한다. 인원 수가 같고 장면 단어가 겹쳐야 하며, 사물과 구체적인 특징도 함께 겹쳐야 한다. 사람·하늘·사진 등의 일반 단어와 같은 장소/인원 수만으로는 후보를 만들지 않는다. 어휘 비교 기반의 초기 규칙이며 이미지 임베딩이나 픽셀 비교는 아니다.

묶음 안의 모든 사진 쌍이 조건을 만족하도록 구성하여 중간 사진을 통한 연쇄 연결을 막는다. 묶음은 최대12장이고 사진이 여러 묶음에 중복되지 않는다. 사진 UUID로 입력 순서를 정규화하고 멤버 UUID의 해시로 묶음 ID를 만든다. 최대2,000장·사진당64개 후보 이웃으로 계산량을 제한한다. 자주 반복되는 특징도 주변의 제한된 후보를 비교하므로64장을 넘었다는 이유만으로 전부 버리지는 않는다.

구도·표정·화질의 우열이나 완전 동일 사진이라는 판정은 하지 않는다. 최초 대표사진은 사진 ID 순으로 정해지며 사용자가 별표로 바꾼다. 선택은 보관함에 공유 저장되며, 묶음 구성 변경 후에도 선택한 사진이 남아 있으면 최근 선택을 이어간다. 표현이 다르거나 인원 수가 달라지면 비슷한 실제 사진을 놓칠 수 있고, 다른 사진이 후보에 포함될 수도 있다. 실제 여행 사진의 정확도 수치는 아직 검증하지 않았다. `중복` 필터는 완전 동일 파일의 반복 업로드와 유사 사진 후보의 합집합을 표시한다. 후보는 현재 보관함에 존재하는 사진이 두 장 이상인 묶음만 포함한다. 분석 상태가 바뀌면 선택한 필터와 비교 후보를 자동 갱신한다. 실제 완전 중복 통합은 기존 SHA-256·파일 크기 기준을 계속 사용한다. 후보를 자동 삭제하거나 병합하지 않는다.

## 화면

일반 사진 목록은 중복 묶음을 대표사진 한 장과 뒤로 포갠 카드·개수로 표시한다. 대표사진을 누르거나 공유보관함의 `비교`에서 후보 묶음을 열고 한 번에 최대4장의 썸네일을 나란히 본다. 마지막 페이지에 한 장만 남으면 이전 사진 한 장을 함께 보여 비교 맥락을 유지한다. 페이지 이동, 사진 선택, 원본 확대, 기존 선택 다운로드를 제공한다. 확대를 닫으면 같은 묶음·페이지와 선택 상태로 돌아간다. 비교 자체는 원본을 자동으로 내려받지 않아 휴대폰의 이미지 디코딩 메모리와 전송량을 줄인다.

일반 목록의 필터는 대표사진에 적용하고, 묶음을 열면 해당 보관함의 전체 묶음 사진을 표시한다. 비교 후보 보드에서는 기존 사진 필터를 적용한 뒤 두 장 이상 남는 묶음을 표시한다. 실패는 명시적 재시도, 진행 중 분석은 숫자/아이콘과 후보 새로고침으로 표현한다. 중복 필터에서도 후보 조회 중 상태와 실패 재시도를 아이콘으로 제공한다. 안내 문구·확신도 백분율·자동 베스트샷 선택은 없다. 다운로드 요청과 실제 수령 확인은 분리한다.

## 권한과 상태

`GET phogaem-similar-get/v1?albumId`도 계정 승인과 앨범 멤버십이 필요하다. 응답은 묶음 ID·사진 ID와 분석 상태 개수만 포함하며 원문 분석 결과를 보내지 않는다. 응답은 private,no-store이며 후보 조회가 모델을 새로 호출하지 않는다.

프런트는 응답 크기·개수·중복 ID를 검증하고 현재 보관함에서 이미 받은 사진 ID만 표시한다. 보관함/계정 전환, 승인 취소, 변경 작업 뒤 늦은 응답은 폐기한다. 일반적인 분석 상태 조회 때문에 사용 중인 비교 창을 닫지는 않는다.

## 검증

합성 메타데이터로 긍정·부정 후보, 잘못된 분석, 현재 버전 필터, 연쇄 연결 방지, 순서 안정성,64/65/2,000장 경계와 묶음 크기를 검증한다. HTTP 테스트는 비멤버·위조 core 헤더·분석 원문 비노출·읽기 전용 동작을 검사한다. 브라우저는 썸네일/원본 구분, 선택·확대 후 복귀·다운로드 원본 보존, 수령 미확정, 필터, 실패 복구, 늦은 응답, 승인 취소,390px 화면과 페이지 이동을 확인한다. 테스트는 실제 R2나 Gemma를 호출하지 않는다.

## 대표사진과 다운로드

`POST phogaem-representative-set/v1 {albumId,groupId,photoId}`는 승인된 보관함 멤버만 호출한다. 서버에서 현재 묶음과 선택 사진을 다시 확인하고 오래된 묶음·다른 보관함 사진을 거절한다. 변경은 공유 저장되며 실패 시 비교 창 안에서 아이콘과 재시도로 복구한다. 진행 중이던 후보 응답은 선택을 덮어쓰지 못한다.

갤러리·전체 선택·비교·원본 확대에서 요청한 새 다운로드는 묶음마다 대표사진 하나로 정규화한다. ZIP에도 대표사진과 묶이지 않은 사진만 포함되며, 다운로드 기록도 실제 전달한 사진에만 추가한다. 비대표 원본은 삭제하지 않고 묶음에서 확대할 수 있다. 후보 조회가 실패하거나 진행 중이면 새 다운로드를 막아 미확인 묶음의 모든 원본을 잘못 받지 않게 한다.

## 오탐 분리

비교 창의 사진별 `분리`는 `POST phogaem-similar-exclude/v1 {albumId,groupId,photoId}`를 호출한다. 승인된 해당 보관함 멤버만 사용할 수 있고, 서버가 현재 묶음과 사진을 다시 검증한다. 선택 사진과 현재 묶음의 나머지 사진 사이에 대칭적인 제외 관계를 저장하며 보관함 멤버에게 함께 적용한다. 새 사진이나 재분석이 끼어도 거절한 두 사진은 다시 같은 묶음에 들어가지 않는다. 모든 미래 유사 사진에서 해당 사진을 영구 제외하는 기능은 아니다.

서버는 변경 후 후보와 대표사진을 반환한다. 분리한 사진은 남아 있으며 독립적으로 다운로드할 수 있고, 남은 묶음에서는 대표사진 하나를 다운로드한다. 동일 바이트를 여러 번 올린 단일 원본의 중복 횟수는 유지한다. 커밋 후 응답 유실에 대비해 같은 요청의 재시도는 현재 후보를 반환한다. 원본 파일·메타데이터·수령 기록을 삭제하거나 변경하지 않는다.
