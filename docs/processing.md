# 업로드 후처리

원본 업로드가 확정되면 DB 트랜잭션 안에서 썸네일·Gemma 작업을 등록한다. 원본 사용 가능 여부와 후처리 성공 여부는 별개다. 대기·실행·완료·실패는 사진별 아이콘과 명시적 재시도로 표시하고 안내 문구/토스트는 표시하지 않는다.

## 처리와 복구

작업 상태는 Postgres에 보존하고 `(photo, kind, version)`으로 중복 등록을 막는다. 전용 DB 연결의 advisory lock으로 작업자는 하나만 실행한다. 썸네일을 우선 처리하고 Gemma는 한 번에 한 사진만 분석한다. 정상 완료 결과만 저장하며 실패를 완료로 표시하지 않는다. 자동 실패 재시도는 하지 않고 수동 재시도는 최대 3회 실행 범위에서 제한한다.

정상 종료·시간 초과·출력 초과·DB 세션 유실 때 작업자는 자신이 만든 프로세스 그룹에만 종료 신호를 보내고 직접 자식을 `wait`로 회수한다. 자식의 stdout/stderr는 제한된 크기로 읽는다. Python 작업은 부모 PID를 감시해 부모 강제 종료 뒤 자신의 변환 그룹도 종료한다. 새 작업자는 잠금을 확보한 후 유예를 거쳐 실행 중 작업을 복구한다. 작업 중인 임시 디렉터리는 완료/실패/재실행 때 정리한다.

LM Studio는 별도 운영 서비스라 종료하지 않는다. HTTP 연결 종료가 추론 종료를 보장하지 않으므로, Gemma 요청 직전에 DB에 120초 슬롯을 확보한다. 정상 결과가 확인되면 해제하고, 시간 초과/중단 시에는 재시작해도 남는 대기 시간이 새 추론 요청을 막는다. 대기 중에도 썸네일은 처리할 수 있다.

## 썸네일

Mac Image I/O의 별도 실행 파일이 픽셀 수·프레임 수·방향을 확인하고 긴 변 최대 640px의 PNG 픽셀 이미지를 만든다. 원본보다 확대하지 않는다. `cwebp`가 WebP 손실 압축(품질 70부터)으로 인코딩하고 128KiB 상한을 확인한다. EXIF/GPS는 출력에 복사하지 않는다. 입력은 16MiB·최대 60MP/변 30,000px·32프레임 이하로 제한하고 CPU/벽시계 시간/출력 크기도 제한한다.

확정된 R2 썸네일은 해시·변환 버전별로 재사용하고 덮어쓰지 않는다. 객체 크기·형식이 장부와 다르거나 유실되면 실패로 처리하여 용량을 작게 집계하지 않는다. 목록은 준비된 썸네일만 요청하고, 준비 중/실패에서 원본을 자동 대체 요청하지 않는다. 크게 보기·다운로드·ZIP은 원본을 사용한다.

## Gemma 메타데이터

준비된 작은 WebP를 loopback LM Studio의 `google/gemma-4-e4b`에 전달한다. reasoning off, 저장 off, 출력 토큰 상한을 적용한다. `scene`, `people`, `objects`, `layout`, `distinctive_details`의 정확한 JSON 스키마와 크기를 검증한 뒤 저장한다. 원본의 촬영일/GPS EXIF 추출 기능은 아직 포함하지 않는다. 모델 별칭의 실제 가중치나 전처리/프롬프트가 바뀌면 작업 버전을 올려 재처리해야 한다. 분석 결과는 유사 사진 후보 비교용 기반이며 완전 중복 판정이나 자동 삭제 근거로 쓰지 않는다.

DB에 결과를 보존하고 화면에는 작업 상태를 표시한다. 공유보관함의 비교 동작은 기존 분석을 읽어 후보 묶음을 만들고 나란히 비교·선택할 수 있게 한다. 기준과 한계는 [비교 후보](comparison.md)를 따른다. 분석 원문을 탐색하는 UI는 제공하지 않는다.

## 운영과 검증

공유 API 11개는 모두 계정 승인이 필요하며 보관함 멤버십을 추가 검사한다. 썸네일도 비공개이고 브라우저 영구 캐시는 만들지 않는다. 진행 중 작업이 있을 때만 화면의 해당 보관함 메타데이터를 주기적으로 확인하며, 완료·화면 전환·승인 거부에서 확인을 중지한다.

백엔드 `tools/test_process_photo.py`는 실제 WebP 생성·거대 해상도 거부와 부모 강제 종료 후 자식/변환 프로세스 종료를 합성 입력으로 검사한다. Rust 테스트는 정상·비정상 종료, 시간 초과, 취소, 출력 폭주, 자손의 열린 파이프를 검사한다. DB 테스트는 중복·재시작·잠금 유실·지속적 추론 대기·수동 재시도 한도를 검사한다. 실제 Gemma 통합 검증은 명시 플래그를 켰을 때만 합성 장면으로 실행한다. 일반 CI에서 실제 추론이나 R2 호출을 하지 않는다.

프로세스 분리와 자원 제한을 구현했지만 전용 OS 사용자/컨테이너 보안 격리까지 제공하는 것은 아니다. Mac 원본 복구본 정리, 고아 객체/예약의 관리용 재조정, 새 변환 버전의 이전 캐시 정리는 후속 운영 작업이다. 불확실한 쓰기의 용량은 확인 전까지 예약으로 유지한다.
